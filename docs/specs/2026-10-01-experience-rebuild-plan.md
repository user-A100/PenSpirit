## 2. 诊断

### 2.1 方向一：UI 观感

**实机观察**

1. **层级关系错了，所以「不像 Zen」**。`App.tsx` 把整个视图放进一张 `rounded + bg-panel` 卡，侧栏、编辑器、右 dock、AI dock 都在卡内用 1px 发丝线分隔——视觉上就是常规三栏。Zen 的要义恰恰相反：**chrome（标签栏/侧栏/工具栏）透明贴在背板上、无描边，只有网页内容是唯一不透明带阴影的卡**。数值（8px sep、`0 3px 8px rgba(0,0,0,.24)`）照搬了，层级没照搬。
2. **右 dock 标签栏损坏**：`lib/nav/registry.ts` 给写作视图挂了 9 个面板，`PanelDock.tsx` 用 `flex-1` 平分一行，常规宽度下每个 tab 只剩图标加半个字。这是「简陋」观感的头号来源。
3. **设计系统没落地**：`components/ui/` 有 Button/Card/Modal/Badge/Input，但 Button、Card 各仅 3 个文件引用；其余到处手写 Tailwind 串。`text-xs` 252 处、`text-[10px]/[11px]` 93 处——没有字号阶梯，密度和层级全靠临场。
4. **视图之间不一致**：碰碰车自带 48px 带边框标题栏；结构/图谱/统计/文风库走 `ViewShell` 的 h1；统计与文风库是 M4「dock 面板升级为一级视图」时直接拉伸的窄表单，宽屏上大片空白、滚动条悬在页面中部。
5. **编辑器 chrome 杂**：顶栏 8 个 14px 灰图标 + 一个文字按钮「打字机」混排，次要动作常驻。
6. **AI dock 常驻占编辑列 32% 高度**，空态时也一样；折叠态是一条 36px 边框条。
7. **动效语言缺位**：全仓 33 处 transition，几乎都是颜色过渡；面板开合、视图切换、列表增删都是瞬变。
8. **原生对话框**：8 处 `alert/confirm`，在 WebView2 里弹 Windows 系统框，破坏沉浸。
9. **死开关**：设置 → 外观「明暗：跟随系统/浅/深」只切 `<html>` 的 `dark/light` 类（`themes/ThemeProvider.tsx:151`），**全仓无任何样式消费这个类**，切了没反应。
10. 主题变量只有 17 个，没有 surface 层级、alpha 填充阶梯、动效/字号/层级 token；10 套主题各自手调值，新增层级 token 要改 10 处。

**我的判断：Zen 好在哪、什么能迁移、什么不能**

- 好在 **「一个焦点」**：全窗口只有内容卡是不透明的，其他一切贴着背板，眼睛不用分辨边界。
- 好在 **「层次不靠线」**：8px 留白 + 一档阴影 + alpha 叠层（hover 7% / active 10% / 元素底 8–15%，全从 currentColor 派生，任何主题自然成立）。
- 好在 **「同心圆角」**：内圆角 = 外圆角 − 间距/2，曲率连续，所以 5–6px 的小圆角也显得柔。
- 好在 **「安静」**：次要控件 hover 才出现，非活动元素去色降透明；动效 0.1–0.25s 无过冲，弹簧只留给 toast/落位这类低频事件。
- 好在 **「浮层工具」**：命令栏、Glance 预览、Toast 都是浮在内容上的临时层，不占布局。
- **迁移到写作软件**：稿纸 = 唯一主卡；Ribbon + 章节树贴背板；右 dock、AI 对话 = 第二层卡；书 = 工作区（可选每书背板色调，切书时淡入）；专注模式 = 紧凑模式（主动进入才自动隐藏）；Ctrl+K 命令面板 = 浮动地址栏；`[[章节]]`/人物卡预览 = Glance；保存/采纳/删除撤销 = Toast。
- **不迁移**：颗粒纹理与渐变进稿纸（长时间阅读疲劳，只放背板且 ≤0.3）；70% 透明度正文；自动隐藏作为默认；大面积 `backdrop-filter`（WebView2 性能差，浮层可用、底层不用）；直搬 14px superellipse（无 `corner-shape` 时成胶囊）；高频操作（切章/保存/打字）的过冲动画。

### 2.3 方向三：侧栏（Binder）与结构视图

**沿 M7/M8 脉络的现状**：Scrivener 研究里已完成「元数据 / 三视图 / 双链 / 集合（含搜索集合）/ 手动集合独立排序 / 分屏与导航历史 / 注入原子 / 自由卡片墙」；计划文档点名但未做的是 **稳定 ID、层级、作用域视图状态**；`codex/collection-review-plans` 分支有两份**未实施**的计划（集合面板刷新可靠性、集合作用域结构视图）。

**差距（按严重度）**

1. **基础功能洞**：后端有 `rename_chapter` / `delete_chapter` / `delete_book`，README 也写了软删除与回收站，但**前端没有任何入口**（git 历史确认侧栏从未接过）。新建章只能靠侧栏常驻输入框；空态文案写着「Ctrl+N 快速新建（即将支持）」。
2. **无层级**：章节表只有 `sort_key`，磁盘 `manuscript/NNNN-标题.md` 平铺。导入器已能识别「第一卷/卷一/Volume 1」，但注释写明「chapters 表无卷字段，不落库」（`porting/import.rs:31`）——**卷结构在导入时被静默丢弃**。中文长篇几乎都分卷，这是与 Scrivener 最大的差距。
3. **结构视图与侧栏互斥**：卡片墙/大纲列/串烧是 Ribbon 上的独立一级视图（`ViewShell` 无侧栏），进入后看不到目录。Scrivener 的核心是「选择驱动、视图只是透镜」——Binder 选什么，编辑区就用当前组视图模式（Ctrl+1/2/3）展示什么，且每个分屏各记一份。
4. **交互原语缺失**：全仓 0 个右键菜单；无多选；无键盘导航；HTML5 原生拖放只有半透明、无插入线、无同级/放入区分、无边缘自动滚动；无过滤；无「在目录中定位」。
5. **信息呈现**：章节行只有图标色（标签）+ 字数；状态、目标进度不可见。注意 Scrivener 的 Binder 本身也不显示字数/进度、也没有保留层级的过滤——这两点正是 Ulysses / Novelcrafter 胜出、我们可以**超越 Scrivener** 的地方。
6. **杂项**：书籍列表与常驻「新书名」输入框占侧栏顶部；「重建索引」按钮占底部黄金位置且用 `alert` 回报；集合是右 dock 的第 3 个 tab，而 Scrivener 中集合是 Binder 顶部标签页。

### 2.4 跨方向的系统性问题

- **错误呈现**：47 处 `String(e)`，结构化错误 `{code,message}` 一律变成 `[object Object]`。
- **反馈层缺失**：无 Toast（无「撤销」通道），8 处原生 `alert/confirm`。
- **无命令/快捷键中枢**：10 处分散的 `keydown` 监听（`App.tsx` 一个文件里 6 个），没有统一的命令注册表——命令面板、右键菜单、斜杠命令、快捷键速查都没有单一数据源。
- **无菜单原语**：右键菜单、下拉菜单都要从零写（现有「检查」下拉是手写 fixed 遮罩）。

## 3. 设计原则（本次重建的取舍标准）

1. **稿纸优先**：任何改动不得让正文区更小、更花或更吵；正文保持中性色与 ≥AA 对比度。
2. **一个焦点**：同一时刻只有一张不透明主卡；其他层靠留白与 alpha，不靠描边。
3. **视图是透镜**：同一份数据（章节/元数据）在目录、卡片、大纲、编辑器里表达一致、互相联动。
4. **结构编辑要便宜且可撤销**：新建一键、移动多通道、删除进回收站并可 Toast 撤销。
5. **所有注入可见**（沿用原规格 §4.4）：AI 用了什么上下文，输入框上方看得见、点得掉。
6. **一处定义、多处使用**：命令注册表驱动快捷键 / 命令面板 / 右键菜单 / 斜杠命令 / 速查表。
7. **渐进**：每阶段可独立交付、可回退；数据层仅允许「增量」变更（见 §6 决策 1）。

## 4. 验证体系（所有阶段通用）

- **自动化**：`vitest`（前端，新增交互测试）、`cargo test`（Rust）、`tsc --noEmit`；每阶段结束全绿。
- **实机脚本**：新建 `scripts/verify/lib.mjs`（CDP 连接、截图、断言、等待）与每阶段一个 `scripts/verify/pN.mjs`。
  - **状态保护**：脚本开始时快照 `localStorage` 全量 + 外观设置 + 当前书/章，结束（含异常路径）逐键还原并断言 diff 为空；所有写操作只发生在脚本自建的隔离测试书里，结束后删除书与磁盘目录。
  - **AI 实机不需要真 Key**：`scripts/verify/mock-llm.mjs` 起本地 OpenAI 兼容 SSE 假服务（可控延迟、截断、429/500），脚本临时注册它为服务商、结束后删除并还原「使用中」服务商。
- **视觉验收**：每阶段产出 before/after 截图集（4 主题 × 相关视图），美学部分以你目测为准——这是唯一无法完全自动化的验收项。

## 5. 分阶段方案

### 为什么是这个顺序

- **0 先行**：Toast/确认框/菜单/命令中枢是 1、2、3 共同依赖；`[object Object]` 和「无法删改章节」是一上手就会撞上的硬伤。

### 阶段 2C：AI P2 ✅

分 4 组提交（bdf6e67 · 3451e00 · 32f571f · 42b2c7c）。16 项全部实现，没有砍掉任何一项；其中 3 项的做法与调研表字面不同（见下表「做法说明」）。

- **2C-1 对话增强**（迁移 `0023_chat_rating`）：消息显示本地时间（库里是 UTC）；Ctrl+F（焦点在 AI 卡里）会话内查找，CSS 自定义高亮、不改消息 DOM；👍👎 评分，按斜杠命令统计（命令库里显示每个自定义命令的 👍 / 👎，用于本地提示词调优）；导出对话为 Markdown（只导出各问题当前选用的回答，标模式 / 命令 / 采纳 / 评分）；另存为新章节（备选稿，紧随本章、同卷）/ 存为素材片段；生成中回车 = 排队，这一轮正常结束后自动依次发出，「立即发送」= 停下当前生成（已生成保留）马上发；一轮 ≥ 10 秒且窗口不在前台时任务栏闪动 + 标题加「✓」。
- **2C-2 输入与上下文**（迁移 `0024_phrase_bias`）：附件（.txt / .md 自动识别编码、.docx 取文字，过长截断），本轮随请求进【附件】块，超预算时先于引用资料被裁；上下文包——@ 引用、关闭的槽位、手选规则加上模式 / 长度 / 温度存成有名字的包，选中后**每轮都带上**（与本轮临时设置合并），按书存、删书时清掉；词语偏置——禁用 / 偏好用词（本书或所有书通用），进 system【用词要求】，回答里出现禁用表达时提示「含 AI 腔 N 处」并可「去掉重写」，可一键导入 20 条常见 AI 腔（不会自动写入）；正文指令——`{…}` 作者批注只给 AI（进【作者批注】并从正文上下文剔除），`[…]` 待写指令：光标放进去按 Alt+Enter，AI 按它写成正文并替换整个方括号。编辑器给两种指令着色，占位符扫描能查出没处理的指令；`arr[0]`、`[1]` 脚注号、`[[章题]]` 都不算指令。
- **2C-3 编辑器内 AI**：幽灵补全（默认关）——停顿 1.2 秒且光标在非空段末尾时，给出半句到一句灰字建议（纯装饰，不进文档）；Tab 接受（标为 AI 写入：不计今日手写、记进着色），Esc、继续打字或移动光标即消失。换个说法——选中一个词，AI 给 8 个近义词 / 成语，同时列出「此处最可能的字」及模型概率：流式请求带 `logprobs` / `top_logprobs`，读到第一个带概率的分片就收手；服务商不回概率时只给近义词并说明。点一个即替换。朗读——选段 / 回答 / 从光标处朗读本章，用系统语音合成按段逐段读，全局朗读条一键停。
- **2C-4 检索与侧聊**：相关章节 / 素材检索——本书各章（排除当前章、剔除正文指令）与全局素材，用字二元组 TF-IDF + 余弦相似度排序，每条命中给出最相关的一段（向前后扩到 1200 字）与摘录。`@` 菜单还没输入时，先列出与光标附近内容相关的项（标相关度 + 摘录），选中即带上相关段落：引用章节时注入「相关段落」而不是章尾；素材也可以 `@`。侧聊——AI 卡里并排的第二个对话，讨论模式、带本章上下文与设定，只带侧聊自己的几轮，不进正式对话、不落库。
- **核验工具**：开发构建里的保存 / 打开文件核验钩子 `__e2eSavePath` / `__e2eOpenPath`（`src/lib/dialogs.ts`，生产构建剔除）；mock-llm 增加近义词 JSON、首个分片带 logprobs、「AI 腔」回答。`withGuard` 增加：还原「所有书通用」的词语偏置条目；关掉应用留在桌面上的原生对话框（文件选择 / 消息框）并判不通过。
