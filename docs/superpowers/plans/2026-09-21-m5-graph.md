# 笔仙 M5「图谱」实现计划：家族树 + 关系网络 + 世界地图

## Context

用户参考 Gramps Web（开源家谱软件）的家族树图表与地图工具，要求强化笔仙的角色卡功能。已拍板三个方向：

1. **通用角色关系 + 家族树过滤**：关系类型自由填写（预设 父母/子女/配偶/兄弟/师徒/仇敌/挚友…）；「家族树」子视图只按家族边自动排谱系
2. **虚构世界地图**：上传地图图片，平移缩放、打地点 pin（名称/描述/关联角色），纯本地离线
3. **落点：新一级视图「图谱」**，内含 家族树 / 关系网络 / 地图 三个 tab

现状：角色表只有基础字段，**关系表、地点概念完全不存在**；前端无任何图/地图库。全部新建，migration 从 **0013** 起步。

## 核心决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 可视化库 | **不引入 React Flow/d3**，手绘 SVG + 自写 `usePanZoom` hook（~60 行，wheel 光标缩放 + 拖拽平移，`{ passive: false }` + preventDefault） | React Flow 不含自动布局还得加 dagre；地图场景用 node/edge 模型是绕路；两处共用一个 hook 一鱼两吃 |
| 关系存储 | 单向存一行，UNIQUE(source_id,target_id,relation_type)；对称类型（配偶/兄弟等）前端视为无向边，查询 `source_id=? OR target_id=?` | 双写需事务同步易脏数据；重复添加静默转更新 note |
| 地图图片 | **存文件目录 `$APPDATA/maps/`，DB 只存 path**，前端 `convertFileSrc(path)` 渲染——**照抄阅读背景图先例**（commands.rs:745 `reading_bg_import_inner`，ext 白名单 + 10MB 上限 + copy） | asset 协议已启用（Cargo.toml L22 `protocol-asset`、tauri.conf L25）；readerBg.ts 注释明确「绝不用 data-URL」；零 base64 IPC 开销 |
| pin 建模 | **不设 map_pins 表**，x/y 百分比（0~100，换图/缩放不失效）直接挂 `places` 行；pin 新建/拖动/改名全走 `place_upsert` | 地点无独立于地图的生命周期；一个命令管全部 pin 操作 |
| 角色关联 | `linked_character_ids` 逗号分隔，不做第四张关联表 | 每书地点几十个量级 |
| 关系编辑入口 | 只放图谱视图（点节点弹 RelationEditModal）；CharactersPanel 仅加关系数 Badge | 窄 dock 塞不下编辑器；两边共用 useRelations store 天然同步 |
| 孤立角色 | 家族树底部「未入谱」灰化行，点选可直接建关系 | 隐藏会让用户找不着角色 |
| 成环兜底 | 布局层 BFS 后未访问角色归「孤岛行」+ 警示 Badge，不崩 | 数据层允许自由关系不设环检 |

## 数据模型 — `src-tauri/migrations/0013_m5_graph.sql`（新文件，建表模板照 0008_m4_characters.sql）

```sql
-- M5 图谱：角色关系 + 世界地图（家族树/关系网络/地图三视图底座）
CREATE TABLE character_relations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  book_id INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  source_id INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  target_id INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
  relation_type TEXT NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(source_id, target_id, relation_type)
);
CREATE INDEX idx_relations_book ON character_relations(book_id);

CREATE TABLE maps (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  book_id INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  path TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE places (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  book_id INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  map_id INTEGER NOT NULL REFERENCES maps(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  linked_character_ids TEXT NOT NULL DEFAULT '',
  x REAL NOT NULL DEFAULT 50,
  y REAL NOT NULL DEFAULT 50,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_places_map ON places(map_id);
```

**在 `src-tauri/src/db.rs` 的 `Migrations::new(vec![...])` 末尾追加注册**（.sql 文件本身不会生效——0011 的教训）。

**家族树布局算法**（familyTree.ts）：① 抽方向边：type 归一化后仅「父母/子女」入谱（父母→子女；「子女」反转）；「配偶」作同代并排依据。② 世代：无父母入边者 gen=0，向下 BFS `child = max(parent)+1`。③ 同层按父节点 DFS 序排子女；夫妻对相邻共用中线，子女垂线从父母对中点引出（多配偶各自聚簇，单亲天然支持）；多根按角色创建顺序左右排开。④ 成环兜底归孤岛行 + 警示 Badge；孤立角色入「未入谱」灰化行。输出 `{ nodes:[{char,x,y}], edges }`。

地图文件选择对话框照 SettingPanel.tsx 现有模式（plugin-dialog）。SVG/pin 颜色全走主题 CSS 变量（--border-subtle/--bg-elevated/--accent 等），禁止写死色值。

## 风险

- **wheel 缩放与页面滚动冲突**：`{ passive: false }` + preventDefault（usePanZoom 内处理）
- **环形关系**：布局层兜底归孤岛行，绝不崩
- **大图性能**：10MB 导入上限；`<img>` 缩放走 GPU；asset 协议直读文件无 IPC 体积问题
- **对称关系重复添加**：UI 查重提示 + DB UNIQUE 双保险
